# 网站子页面快捷入口

用户已确认实现上一轮提出的「分组 → 系统 → 子页面 → 环境」。沿用 Swift/AppKit 原生设置和启动器，兼容已有 v1 单地址和 v2 多环境配置。

## 数据与选择

采用系统环境地址复用页面路径，避免每个组合重复建系统。另一种方案是把 avatar-management 建成独立系统，虽然无需新增结构，却重复维护环境且无法自然列出系统子页面，因此不采用。

配置 version 3 新增系统 `pages`，页面包含 key、name、path、aliases、urls。path 使用站点根路径（以 / 开头，可含查询和片段）或完整 HTTP(S) 网址。urls 是可选的环境 key 到完整网址的覆盖；未覆盖环境使用 path。没有通用 path 时必须覆盖全部已配置环境。单地址系统的页面直接在 path 填完整网址，不使用环境覆盖。

`/admin` 从站点根目录解析，不追加基础地址原有路径、查询或片段。保留编码、端口、页面查询和片段；禁止协议相对路径、反斜线、空白和无效网址。覆盖只能引用系统已配置的环境 key，不猜测别名。

每系统最多100页面，整体仍限制1MiB、100分组、5000系统、5000最终地址（首页和页面分别计数）。旧配置不会自动重写；新增页面时手动保存升级v3。

## 命令

- `ops avatar`：首页和子页面候选，各自带环境与完整地址；首页排在子页面前。
- `ops avatar management`：管理页的各环境。
- `ops avatar management prod`：管理页的生产地址，回车打开。
- `ops avatar prod` 或 `ops avatar home prod`：生产首页，保留既有环境命令。
- `home`、`首页` 保留为首页入口；页面可以配置管理、managment等别名。

完整系统简称或别名优先；其后依次匹配页面与环境。明确输入但未命中的页面或环境不回退首页，也不转公共搜索。每个页面/环境结果有独立稳定标识；仅显式执行才打开浏览器。

## 编辑

系统编辑表单保留单地址/多环境切换，追加子页面区域。环境完整网址覆盖置于可展开的高级区域。环境改名或删除后已有覆盖不丢弃，显示待修复条目并由统一验证阻止错误保存。页面新增、删除、路径、别名和覆盖均纳入脏状态；表单可滚动，保存/取消固定在底部。
