# ADR 0007：知识库插件复用同源 Web 编辑器

- 状态：已废弃（知识库功能已从应用中移除）
- 部分取代：[ADR 0001](0001-native-swift-over-tauri.md) 中全部界面无 WebView 的约束
- 保留：[ADR 0002](0002-built-in-modules-over-plugin-runtime.md) 的内置模块，不引入通用运行时插件系统

## 决策

启动器和已有本地工具继续使用 Swift/AppKit/SwiftUI。仅 DontsKb 官方插件窗口按需创建 WKWebView，加载用户配置来源的 `/tool` 页面，复用正式文章的 Tiptap 编辑器、自动保存、本地草稿、修订冲突、收集箱与认证客户端。

这是因为重写一个原生编辑器会复制知识库正文与保存契约，容易损坏结构、附件与草稿。原生窗口负责标题、置顶、加载错误和关闭协调；Web 页面负责内容编辑与同步。在启动器明确打开一个任务时创建工作窗口；工作窗口内搜索、文章和返回默认同窗，只有“新窗口打开”另开文章。用户于本日实际体验后确认此收敛。同一文章的多窗口编辑依靠现有保存修订与冲突机制。

## 边界

- 来源只接受 HTTPS，开发时允许 HTTP localhost/127.0.0.1/::1。不接受账号、路径、查询与片段形式的配置。
- 所有 WebView 使用默认 WKWebsiteDataStore。登录由页面自身管理，原生桥没有 JWT、刷新凭据或密码操作。
- 主框架桥仅处理固定协议消息；不允许普通同源页面替代插件路由。外部 HTTP(S) 链接交给系统浏览器。
- 空启动器查询只提供本地入口。显式 `kb 关键词` 才创建隐藏搜索桥，打开知识库窗口才加载可见页面。隐藏搜索桥会保留登录维护所需的 Web 生命周期，退出时释放。
- `collect 文字` 用 RPC 送入待确认队列，用户明确追加后进入原有草稿，不把原文放 URL 或自动创建服务器内容。
- 关闭、重新加载和退出先运行既有 departure guards。全局退出时已确认窗口锁定交互，后续拒绝则恢复，防止检查后继续编辑。
- 不采用本地文本工具退出丢弃草稿的策略。未知写入结果继续由知识库机制核实，不因窗口关闭重试盲目重复写入。

## 上线

本地代码和参考设计不等于线上能力。需要另行授权发布 DontsKb Web `/tool` 路由，再在 DontsTool 设置服务来源并登录；协议未就绪时明确提示。当前任务不推送、不部署、不修改真实知识库内容。
