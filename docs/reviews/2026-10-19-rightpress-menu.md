# 普通右键菜单与两秒长按修复

用户报告：浏览器普通右键无法唤起菜单，希望只在持续按住约两秒时翻译。

## 排查和调整

- 原实现提前截住 down，再通过 `postToPid` 把 down/up 直接塞给进程。该路径不等同于原生 WindowServer 分发，存在浏览器鼠标事件兼容性风险。仅增加等待时间无法修复投递路径。
- 原实现 0.5 秒触发，且 mouse-up 也会推断长按并启动翻译。新回归测试证明旧实现在 1.5 秒按压、阈值前后与延迟松开场景失败。
- 新实现持续按住满两秒、有效选区且右键仍按住才触发；mouse-up 始终不启动翻译。
- 普通短按在松开回调中通过当前 `CGEventTapProxy` 补回原始 down，再返回真实 up。根据 Apple 的 API 保证，补回事件排在回调返回事件之前。不再使用直接 PID 投递。
- AX 失败或超时后保留待恢复的 down，直到下一次原生回调有可用 proxy，再还原短按或拖动。停止监听的兜底走 session 事件流，并使用重放标记防止循环。
- 捕获原始 CGWindowID，在重放前重新命中测试，要求相同前台 PID 和相同窗口；被浮窗遮挡、关闭或焦点变化时不把原事件发给新窗口。

## 验证

- Core 216 项测试通过，包括新增的 1.5 秒短按、持续两秒单次触发、松开后不翻译。
- 原生／WebKit 14 项测试通过，覆盖当前 tap 还原路线、原始鼠标数据、session 兜底及 PID／窗口变化时禁止还原。系统投递边界使用替身，测试不会向桌面合成鼠标事件。
- Release 0.1.3 本地构建和 ad-hoc 签名验证通过，包含 arm64/x86_64。
- 独立复审发现的重放时窗口校验问题已修正，复审未发现剩余确证 P1/P2。

真实浏览器菜单和物理两秒长按尚未验收。原生界面控制返回 `noWindowsAvailable`，DontsTool 窗口连接超时，因此不能把上述测试当作菜单已恢复的证据。需要安装候选修复版后验证普通右键、1.5 秒松开、两秒保持、拖动取消。

API 依据：[Apple CGEvent.tapPostEvent](https://developer.apple.com/documentation/coregraphics/cgevent/tappostevent(_:))；本机 SDK `CGEvent.h` 对事件顺序有相同说明。
