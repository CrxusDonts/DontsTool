# GitHub Releases 更新功能验证

## 已实现

- Sparkle 2.10.1 应用内检查、下载、安装和重启。
- 应用菜单、状态栏菜单和设置「关于」入口；默认每日检查，可关闭。
- 更新包 Ed25519 签名，解压前验证；公钥入库，私钥仅在本地忽略目录及 Actions Secret。
- 同短版本、旧版本和预发布版本不安装，不依靠本地/CI 构建号大小判断降级。
- 更新与系统退出共用进行中的保存操作，已经冻结并批准关闭的文档不会重复确认。
- 保存拒绝时保留待安装状态；安装中止时使回调失效，等待正在进行的冻结结束并恢复编辑。
- Release 生成并上传 appcast，与 ZIP、manifest、校验和一起下载回验。

## 安装与重启演练

使用独立 bundle identifier 和临时安装目录的 Sparkle 验证应用，不启动或替换正式 DontsTool，不访问其便笺数据。测试 feed 仅监听本机 loopback，正式应用的 feed 配置仍为固定 HTTPS GitHub URL。

先提供无效签名，框架拒绝安装，已安装测试应用保持版本 1。再提供合法签名，记录：

```text
LAUNCHED 1
CHECKING
FOUND 2
DOWNLOADING
EXTRACTING
READY_TO_INSTALL
INSTALLING
LAUNCHED 2
RELAUNCH_SUCCESS
```

演练证明 Sparkle 的实际下载、归档验证、应用替换和重启通路；文档保存与冻结恢复由真实 WebKit 和协调器回归测试覆盖。未将 GitHub 生产匿名更新或标准更新窗口的人工视觉验收计入此演练。

## 审查修复与实施判断

1. 更新前保存之后，Sparkle 发送正常系统退出事件。修复前，真实 WebKit 测试观察到 snapshot/prepareClose 调用两次；修复后冻结文档只调用一次，恢复编辑后会重新检查。新窗口拥有独立会话，不继承其他窗口的批准。
2. 失败恢复先使待安装回调失效，等待进行中的保存结束，再解除便笺与知识库冻结，防止恢复后又被迟到的保存重新冻结。
3. 沿用当前干净功能分支，没有增加 worktree；本次未观察到并行文件冲突。
4. 将审查指出的等长篡改测试覆盖视作安全验证要求并补齐，没有延期的小问题。

## 历史身份处理

用户授权的强制推送已完成。远程 `main` 为 `0d042b7`，14 个提交和 10 个注释标签的作者、提交者及标签创建者均使用 Donts 和 GitHub noreply 邮箱。每个提交和标签对应的代码树均核对不变。9 个既有 Release 的附件保持不变，CI/Release 工作流已恢复。

本地备份保留在仓库外。强制推送只替换当前分支和标签可达的历史，不会删除其他人的旧克隆或保证 GitHub 旧对象缓存被清除。

## 尚未上线的部分

仓库仍为 private。应用无需登录的产品设计已经实现，但当前发布源无法匿名读取，因此未宣称线上更新可用。公开当前仓库或改用独立公开 Release 仓库，是正式上线前需由用户确定的发布选择。本次没有公开代码、创建正式 Release 或覆盖已安装应用。

0.2.6 及更早版本没有更新器；首次需要手动安装含更新器的 0.2.7，之后才可应用内更新。
