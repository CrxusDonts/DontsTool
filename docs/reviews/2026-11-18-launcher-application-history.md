# 最近应用改为仅统计启动器打开

## 原因与行为

原实现订阅系统应用激活通知，在 DontsTool 运行期间，切换到应用也会更新其最近时间；空搜索按这个时间倒序取四个，不足时还会用其他索引应用填充。

用户要求的范围是从启动器打开的应用。本次删除系统激活的历史写入，只在应用结果的打开动作成功后记录时间并累计次数。最近列表只接受有打开次数和可信时间的应用，按时间倒序取最多四个。没有历史时为空，输入应用名仍能搜索全部应用。频率和名称两种模式保留原有范围。

旧版本时间混合了系统切换，无法还原准确启动器顺序。一次性迁移移除零次数系统记录，保留真实打开次数，将旧应用时间标为未知；下次从启动器打开后，应用重新进入最近列表。网址和文件历史不变，后续重启不会重复清理新时间。

## 验证

- 新回归测试先观察到七项失败；初步修复后，进一步补充未知旧时间不应出现在最近列表的测试，先失败后修复。
- Core 全量 445 项通过，原生 bridge 全量 144 项通过。
- 覆盖旧记录迁移、次数与非应用历史保留、迁移幂等、最近/频率/名称排序、打开失败不计数和未使用应用可搜索。
- 独立审查未发现需要修复的重要问题。随后收紧未知旧时间的筛选规则，并用回归测试确认频率仍保留旧次数、成功打开可恢复最近时间。
- 应用构建验证通过。没有改动当前已安装应用，没有推送或发布。

当前改动在 `codex/launcher-app-history`，此前的更新器和翻译优化分支保留。
