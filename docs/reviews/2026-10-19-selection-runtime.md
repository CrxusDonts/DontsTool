# 划词翻译本机运行诊断

授权重新添加后，当前进程的 active session event tap 已启用，但用户仍报告浏览器选词后持续按压触控板不能弹出翻译。此前的纯状态机与卡片测试没有覆盖真实取词链路。

## 已核实

- 30 秒只读采样中，物理右键连续按下最长约 2.37 秒，session 状态最长约 2.36 秒；两者只在一个采样点不同。不能据此将故障归因于用户没有真正按下、按压不足两秒或 session 按钮状态始终为 false。
- 按压期间 183 个采样点均满足原有前台窗口 owner/layer 校验。采样不是原始 tap 回调，不能排除回调中的 event target PID 校验失败。
- 新增固定阶段诊断：窗口过滤、取词失败原因、250ms 超时、移动或其他输入取消、计时器与卡片触发。只记录阶段与时序，不记录选区、网页内容、API 凭据或响应。设置中显示最近一次操作。
- 诊断候选为 0.1.3 build 2；Universal Release 构建、严格签名校验、216 项 Core 测试和 14 项原生测试通过。尚未宣称运行问题已修复。

## 本机签名

本机诊断候选改用固定自签名代码签名证书。身份存在 Git 忽略的 `.signing/local/` 独立钥匙串，未添加系统信任、未改变发布流水线。签名时将独立钥匙串临时加入搜索列表，并在 finally 恢复原列表；后续本机候选必须复用该身份，不重新生成。身份元数据含秘密，禁止输出或提交。

当前指定要求由 identifier 与证书指纹构成，不再限定具体可执行文件的 cdhash。已在独立副本中改变构建元数据后重新签名，验证新旧 cdhash 不同、指定要求相同，且新文件满足已安装版本的身份规则。首次切换身份仍需重新添加辅助功能授权；后续更新的实际授权继承仍待验证。
